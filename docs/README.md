# ドキュメント（`docs/`）インデックス

このディレクトリには、リポジトリルート [`README.md`](../README.md) では触れきれない設計・運用の詳細ドキュメントを配置しています。PulseBoard は Python 分析 API・Go ヘルスチェッカー・TypeScript API ゲートウェイの 3 サービスで構成されるため、サービス横断で参照するドキュメントは本ディレクトリに集約しています。

## 目的別インデックス

### 全体像を把握したい

- **[ARCHITECTURE.md](./ARCHITECTURE.md)** — 3 サービス（`analytics-api` / `health-checker` / `api-gateway`）の責務、サービス間通信、データフロー、コンテナ構成を整理したドキュメント。「どこを触るとどこに影響するか」を掴みたい時の起点。

### 運用中に困っている

- **[OBSERVABILITY.md](./OBSERVABILITY.md)** — 各サービスが出力するログ・メトリクス・ヘルス指標、外部から観測する方法、Grafana / Prometheus 等との統合ポイントをまとめたリファレンス。「本番で今何が起きているか」を可視化する側のドキュメント。
- **[RUNBOOK.md](./RUNBOOK.md)** — 起動・停止・再起動、環境変数の切り替え、Docker Compose での立ち上げ、想定される定常運用手順を集約した実行手順書。

### 障害対応・切り分け

- **[TROUBLESHOOTING.md](./TROUBLESHOOTING.md)** — 「サービス間通信が失敗する」「ヘルスチェックがフラップする」など、発生しがちな不具合とその切り分け手順・対処法。

## その他のリファレンス

- リポジトリルート [`README.md`](../README.md) — 特徴・技術スタック・ローカル開発の入口
- [`CHANGELOG.md`](../CHANGELOG.md) — 各バージョンで加えた変更のサマリ
- [`CONTRIBUTING.md`](../CONTRIBUTING.md) — コントリビュート時のブランチ運用・コミット規則
- [`SECURITY.md`](../SECURITY.md) — 脆弱性報告手順
- [`CODE_OF_CONDUCT.md`](../CODE_OF_CONDUCT.md) — コミュニティの行動規範

## ドキュメントを追加・更新する時のガイド

- 新しく `docs/` にドキュメントを追加した場合は、本ファイルの該当セクション（全体像 / 運用中の困りごと / 障害対応・切り分け）に 1〜2 行の説明と共にエントリを追加してください。
- リンクは可能な限り **リポジトリ内相対パス** で書いてください。相対パスは GitHub 上でも `git clone` 後のローカルビューでも同じように解決でき、リポジトリ移設や rename の影響を受けにくくなります。
- ドキュメント本文の記述スタイル（見出しレベル・箇条書き・注記の書式）は既存ドキュメントに合わせてください（README.md の書式が事実上のリファレンス）。
- サービス固有の詳細（例: `analytics-api/` 特有の設定手順など）は、そのサービスのディレクトリ配下に README を置くほうがオーナーシップが明確になります。ここに集約すべきなのは、複数サービスを横断する視点のドキュメントです。
